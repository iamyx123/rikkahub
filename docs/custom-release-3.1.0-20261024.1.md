# 3.1.0-custom.20261024.1

版本号 200，沿用现有 GitHub releaseDebug 包名和签名，可覆盖安装。

这次修复 Class Record 整理一节课时反复调用工具、把整份课堂档案塞进上下文的问题：

- 优先用 `get_lesson_context` 一次读取课程正文、现有原话、板书 OCR、资料索引和真实缺口。服务端分包由客户端在一次模型工具调用内连续读取，检查哈希和位置；超出读取预算时保留续读标记。
- 普通 `fetch` 默认读取正文，完整档案仍可显式选择；转写通常只传一份有效文本，需要对照原始 ASR 时仍可选择完整变体。
- 同一回答内相同查询只执行一次，并发重复也会合并；重复调用返回简短提示，不再传入整份相同结果。下一轮用户消息会重新读取。
- 已分页的课堂正文不再被工作区通用策略截成 4 KB 预览后要求 AI 再用 shell 读取。
- Class Record 与已有课堂 MCP 连接都采用上述策略。工具能力定期刷新，避免沿用旧工具目录。
- 共享课堂读取规则只注入一次，删除各工具重复的说明；服务端批量工具不再重复嵌入所有子工具 schema，错误参数会明确报错。
- 待转写、待 OCR 时，用已获得资料完成可核实部分并说明缺口，避免同一回答内反复轮询或擅自检索其他班填补。

本版只优化资料读取、Token 使用和调用策略。录音转写由另一项工作处理；没有修改采集端或重跑转写。

验证结果与测量口径见随包 verification.json。资料体积的 token 对比使用 o200k_base 分词器，不代表实际供应商计费，也不代表任意模型都固定只调用两次。真机端的模型决策和课堂资料完整性需在安装后继续观察。
